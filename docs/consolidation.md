# Community consolidation record

This packaging change keeps the current Hub in place, imports the standalone firmware under a prefix, and moves the historical Python server into a clearly named component. It does not archive, delete, rename or change any source GitHub repository.

## Source identities

| Component | Source commit | Import treatment |
| --- | --- | --- |
| Hub base | `b8e2542dfcee5866f7f7e9e7c51b69ccf7653fb2` in `jeffreydwalter/picobrew-server` | `hub/` paths and content preserved. |
| Standalone firmware | `63c49d01784fb502c56fa85b709472e02f923d78` in `jeffreydwalter/picobrew-pico-pro-firmware` | Entire tracked source tree, unchanged, at `firmware/`. Source tree hash: `33d86c6b3af76450cec616366bff0d0a847ef02c`. |
| Historical Python server | Existing server files inherited from commit `aa7531965c32d124643797937177431cf9dd1c8d` | Paths move to `legacy/zymatic-server/`; original README, MIT license, dependency lock and assets retained. |

Machine-readable identities are in [import-provenance.json](import-provenance.json). The firmware import is an auditable source snapshot identified by its source commit and exact tree hash. Its complete history remains in the [original firmware repository](https://github.com/jeffreydwalter/picobrew-pico-pro-firmware/commits/feature/standalone-rest-api); this consolidation does not rewrite that history or claim it as ancestry of the server repository.

The snapshot was prepared with `git read-tree --prefix=firmware/ -u` from the pinned firmware commit. Publication through the GitHub Git Data API transfers the source blobs and trees into this repository, then records a normal import commit. The source repository's commit objects are not treated as parents that already exist in the destination repository.

## Optional wiki submodule

- Repository: `https://github.com/hotzenklotz/picobrew-server.wiki.git`
- Commit: `b9c4d9435becca2a0ff480a8eb7d1599d6e75d9c`

It was an optional documentation checkout rather than server code. Its pointer is replaced by this record and the original README's upstream wiki links. This avoids a submodule download during a community checkout and does not redistribute wiki contents with an unverified license.

## Automation and compatibility

- Existing `hub/` development paths, Go module identity, Compose configuration and runtime data paths are preserved.
- Firmware paths inside its component remain unchanged. The root CI wrapper adjusts only the execution directory and artifact paths.
- The old Python test/PyPI workflows move with the legacy component and are no longer active repository workflows. They retain their historical contents; this packaging change does not modernize or publish the Python package.
- Local API keys, machine backups, Hub databases and dependency caches are not part of the import.
- The machine-management update published as `95a78829b2b384025aed2c0f07f250cd1de31c83` is included after the initial import. Overview and machine detail pages own connection management, and shared API credentials are reported without rejecting existing configurations.

## Validation scope

Packaging verification compares the imported firmware subtree's Git tree to the source tree, checks that Hub source is unchanged, checks that legacy files retain their original blobs, and validates workflow path prefixes. Firmware images are not regenerated by the consolidation. Physical device testing and stock-protocol adapters remain outside this packaging change.
